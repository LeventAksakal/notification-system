# Contracts are written first; handlers, queries and migrations are generated from them (0004)

## Rule
`api/openapi.yaml`, `schema/*.sql` and `internal/store/queries/*.sql` are the sources. `*.gen.go`, `internal/store/sqlc/` and `migrations/` are generated and never edited by hand.

## Context
Deliverables: "Swagger/OpenAPI specification" and "versioned schema changes". Several agents write code in parallel, so the seams between them must be machine-checked, not agreed in prose.

## Options
1. Spec-first API with oapi-codegen (strict server, requests validated against the spec at runtime); SQL written by hand and compiled to typed Go by sqlc; desired schema in `schema/`, versioned goose migrations generated by Atlas and embedded in the binary. Drift between spec, code and schema fails the build or CI.
2. Code-first: handler annotations generate the spec (swaggo), an ORM (GORM) generates queries and migrations. Less to write up front; the spec can lag the code, and the claim query (0003) needs exact SQL an ORM hides.
3. Hand-written handlers, hand-written SQL through `database/sql`, hand-written migrations. No tools; every mismatch is found at runtime.

## Decision
Pending. Recommended: option 1. List pagination is keyset (`created_at, id` cursor) so pages stay stable while rows arrive.

## Confirmation
CI runs `go generate ./...` and fails on any diff; `task migrate:check` fails when `schema/` and `migrations/` disagree; the guard hook denies edits to generated paths.

## As built (14 Nov 2026)
List pagination is keyset on `id` alone (`ORDER BY id DESC`, `internal/store/list.go`): ids are UUIDv7, so id order is creation order and one column replaces the `created_at, id` pair. The indexes are `(channel, id)` and `(status, id)`.
