Behaviour when Valkey is down (not a row of the brief; found by the final verifier): the API keeps accepting within its normal time, workers send nothing, WebSocket streams are closed rather than left with holes. Proven by `TestGapOutageBatchAcceptedPromptlyWithValkeyDown`, `TestGapOutageAPIServesWithValkeyDown`, `TestGapOutageWSClosedWhileFeedLost`, `TestGapOutageWorkerSendsNothingWithValkeyDown`.

Run one row's proof: `go test -tags integration ./test/acceptance -run '<test name>'`.
