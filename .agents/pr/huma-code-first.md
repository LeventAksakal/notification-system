# The server's endpoint code owns the HTTP contract: Huma v2, generated spec and client (decision 0024)

Not pushed and no PR, per the owner (15 Nov 2026): the coordinator merges the worktrees locally and pushes once. This file is what the PR description would have been.

## What changed
- **Server on Huma v2** (humago adapter on `net/http` ServeMux). There are 14 operations in `internal/httpapi/api.go`, with their types in `contract.go`. Huma validates each request before the handler runs. kin-openapi request validation, the oapi-codegen strict server (`api.gen.go`, 2,767 lines) and `validation.go` are gone.
- **Error model kept:** `errors.go` replaces `huma.NewError`/`NewErrorWithContext`:
  - Huma's 400, 415 and 422 become 400 `invalid_request`, with `details[].field` naming the JSON field or parameter and `index` the batch position;
  - 413 becomes `request_too_large`;
  - 422 is used only for a reused Idempotency-Key;
  - a database outage is 503 `unavailable` with `Retry-After`; anything else is 500 `internal` with no internal text.
- **Limits from one place:** schema limits are read from `internal/notification/limits.go` through `TransformSchema` and `SchemaProvider`. `MaxCursorLen = 255` was added there, since the cursor limit was only in the YAML before.
- **Spec generated and committed:** `go generate` (`task gen`) runs `internal/httpapi/specgen`, which writes `api/openapi.yaml` (OpenAPI 3.0.3, version 1.3.0) with a generated-file header. `/openapi.json` serves the same document, built at start-up.
- **Typed client:** `test/apiclient/client.gen.go` is generated by oapi-codegen v2.8.2 from the committed spec and covers all 15 operations, including `StreamEvents` and `StatusEvent`. Why oapi-codegen: it emits plain `net/http` code with one typed response per status code, its only runtime is `oapi-codegen/runtime` (already in go.mod), and it is what any Go consumer of the spec would use. The acceptance tests now drive the API through it, and every hand-written response struct is gone. Raw HTTP remains only where a typed client cannot express the input (a missing required field, a non-UUID path id, a repeated query parameter, exact over-limit byte counts) and for routes outside the contract (`/openapi.json`, `/docs`, the WebSocket dial).
- **WebSocket:** `/v1/ws` stays a plain `net/http` handler outside Huma routing. It is added to the spec by `documentStream`. Huma prunes schemas nothing references, so the operation carries `x-websocket-message: {$ref: StatusEvent}`, and `StatusEvent` comes from `contract.go`.
- **Docs page:** `/docs` keeps the vendored Scalar bundle. Huma's built-in docs page loads Scalar 1.76.0 from unpkg.com, and the requirement is that `/docs` calls no other host.
- **CI:** the static job gets a step "API contract keeps every client working": `oasdiff breaking --flatten-params --fail-on ERR` against the base revision's `api/openapi.yaml`. oasdiff v1.38.0 is pinned in `tools.mod`; locally, `task api:breaking [BASE=main]`, and `task doctor` prints its version. `.gitleaks.toml` allowlists `go.sum`/`tools.sum` paths: the kin-openapi module hash `h1:Qo4q…` matched `generic-api-key`.
- **Guard:** `.claude/agent-policy.json` marks `api/openapi.yaml` as generated (Write/Edit denied to everyone; regenerate with `go generate`). It marks `internal/httpapi/api.go` and `contract.go` as contracts (coordinator only). An implementer lane whose diff regenerates the spec fails `tools/ownercheck`. The rules in `.claude/rules/schema-and-api.md` (now also loaded for `internal/httpapi/**`) and in `go-code.md` are updated.
- **Decisions:** record 0024 is accepted; decision-makers: owner in chat, 15 Nov 2026. It opens with the Question and lists three options: spec-first oapi-codegen, code-first Huma (chosen), swaggo, plus the owner's ownership argument. 0004 moved to `docs/decisions/superseded/` with its banner; its SQL half and keyset pagination still hold. `docs/decisions/README.md`, `CLAUDE.md`, `README.md` and `docs/briefs/CONTRACT.md` are updated. `go test ./tools/adrcheck` passes.
- **Outside internal/httpapi:** no change to `internal/delivery`, `internal/intake`, `internal/realtime` or `internal/notification/ports.go`. Compilation did not force any.

## oasdiff against main's api/openapi.yaml (1.3.0)
```
$ go tool -modfile=tools.mod oasdiff breaking --flatten-params --fail-on ERR base.yaml api/openapi.yaml
No breaking changes to report, but the specs are different.
Run 'oasdiff diff' to see structural differences.
exit 0

$ go tool -modfile=tools.mod oasdiff changelog --flatten-params base.yaml api/openapi.yaml
No changes to report, but the specs are different.
exit 0
```
Why `--flatten-params`: without it, oasdiff reports 3 errors, `new-request-path-parameter` "added the new path request parameter `name`" on GET, PUT and DELETE `/v1/templates/{name}`. The parameter only moved from the path item onto each operation. Moving it the same way in main's spec alone, then re-diffing, gives "No changes", so the report is a false positive.

What differs structurally, none of it breaking, so the version stays 1.3.0:
- The info description text.
- Parameter and header descriptions moved into their schemas, and `explode: false` was added on scalar query parameters.
- **Parameters and response headers are inline instead of `$ref`s to `components.parameters`/`components.headers`.** The wire is identical. A client generated by oapi-codegen loses the named types `IdempotencyKey`, `CorrelationId`, `Limit` and `Cursor`, and the list of templates becomes the named schema `TemplateList`. A Go consumer that used those type names must rename them when it regenerates.
- `x-websocket-message` on `/v1/ws`.

## Behaviour changes a client could notice (all on bad input)
- Validation reasons are worded by Huma now (`expected length >= 1` rather than `minimum string length is 1`). Reasons were never part of the contract. The field, index and code are unchanged for all 92 captured bad inputs (old server against new, in-process).
- Details for one request come in Huma's order: "missing to and channel" lists `channel` first.
- Stricter: data after the JSON value (`{...} x`) is now 400; it used to pass. "List with many bad parameters" also names `batchId`, and "batch get, bad id and limit" names both.
- `GET /v1/notifications/batch` is 400 (bad id) where it was 404. HEAD is answered on GET routes.
- `/healthz` and `/readyz` print JSON keys in another order.

## Verifier
Full report: `.agents/reviews/2026-11-15-code-first-api.md`. Two passes, both by a fresh-context verifier.
- **First pass: FAIL.**
  1. HIGH: `?batchId=URN:UUID:…` passed Huma's uuid check and panicked `uuid.MustParse`. Fixed: `uuidParam`/`parseUUID`, test added.
  2. HIGH: HEAD's TestR10LimitsAgreeSpecAndCore read `components.parameters`. Fixed by the test-writer: it now reads each operation's parameters and adds a cursor check. The lost component names are stated above.
  3. MEDIUM: Huma accepted null for optional fields the spec does not declare nullable. Fixed: `refuseNull`.
  4. LOW-MEDIUM: a repeated header was accepted. Fixed: `singleValues`.
  5. LOW: an empty `Idempotency-Key` created without a key. Fixed for every parameter with minLength ≥ 1.
  6. LOW: an unknown property with a dot in its name was misnamed. Fixed.
  7. LOW: stale docs. Fixed.
- **Second pass: PASS with low findings.** The fixes are correct. The acceptance diff only adapts the tests: no assertion was removed or loosened, and several got stricter. Low findings:
  - null details dropped Huma's other details. Fixed: one 400 carries both.
  - Bodies are buffered once more before Huma reads them, and parsed again only if they contain the bytes `null`. Kept: at most an 8 MiB copy, against a POST dominated by the database. Worth watching in the k6 run.
  - Path ids refused `URN:UUID:`. Fixed.
  - Missing tests for a repeated X-Correlation-ID and an empty cursor. Added.
- The test-writer found one regression the verifier did not: GET by id dropped an empty `deliveryAttempts: []` (`omitempty`). Fixed with `omitzero`; the spec is unchanged.
